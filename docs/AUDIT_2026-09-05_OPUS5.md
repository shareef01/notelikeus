## C. Architecture map

Verified by reading current source (spot-checked against the handoff; not blindly trusted).

```
Web (React 19 + Zustand + Vite PWA)
  UI → stores (notes, auth, tombstone, settings, ui, labelRegistry)
     → noteActions
     → IndexedDB notesLocalRepository (namespaced by ownerId; guest = GUEST_OWNER_ID)
     → notesSyncService → supabaseRemoteNotesDataSource → RPC + Realtime
  Attachments → Cloudflare Worker → R2 (objectKey on the note)

Kotlin (KMP composeApp: Android + desktop)
  Compose UI → ViewModels → NoteRepositoryImpl
     → Room + SQLCipher (Android). Desktop SQLite is unencrypted (accepted, documented).
     → NoteSyncEngine → SupabaseNoteTransport → same RPCs
  Android sync: per-note WorkManager via CloudNoteSyncCoordinator
  No Kotlin delta-subscribe path (web Realtime only)

Backend (supabase/migrations)
  notes, note_tombstones, sync_meta, note_attachments
  RLS enabled; mutations through SECURITY INVOKER RPCs; sync_mutation_guard blocks direct writes
  Server sequence revision + server_updated_at (client clock cannot win a confirmed conflict)
```

**Duplicated logic that must be audited together** (still true):

| Concern | Web | Kotlin | Worker / DB |
|---|---|---|---|
| Backup import caps | `web/src/lib/backup/*` | `NoteBackupImporter.kt` | Postgres CHECK |
| Conflict resolution | `remoteMerge.ts:shouldUploadOverRemote` | `NoteSyncEngine.cloudWinsConflict` | `apply_note_change` base revision |
| Attachment object keys | `attachmentObjectKey.ts` | `AttachmentObjectKey.kt` | `workers/attachments/src/objectKey.ts` |
| Field caps | editor `maxLength` + save clamp | `EditorViewModel` clamp (this session) | `char_length` CHECKs |

Conflict helpers were re-read this session: when both sides have `serverUpdatedAt`, the higher
stamp wins; equal stamps break on client `timestamp` with a tie going to cloud; a confirmed
remote beats an unconfirmed local. Web `>` vs Kotlin cloud-wins `>=` on the remote timestamp are
equivalent. **Statically aligned.** Two-client live races remain **Blocked** (need two clients +
local stack).

## F. Security assessment

**Grade: statically reviewed, DB tests blocked.**

### What still holds (re-read / unchanged from prior session of this audit)

- Five tables: RLS + `owner_id = auth.uid()`. RPCs are `SECURITY INVOKER`, `search_path = public`, owner from `auth.uid()` never from a parameter.
- `sync_mutation_guard` flag is transaction-local, set only inside RPCs.
- `register_note_attachment` requires `object_key == expected_attachment_object_key(auth.uid(), …)`.
- `REVOKE … FROM PUBLIC, anon` pattern in later migrations — new function signatures still get default grants; anyone adding RPCs must revoke.
- Worker: token verified against `/auth/v1/user`; R2 key derived from auth id; MIME allowlist; size cap on `Content-Length` and streaming read.
- Web `src/`: no `innerHTML` / `dangerouslySetInnerHTML` / `eval` / `new Function` (grep this session).
- Markdown links: `toSafeHref`. SW `postMessage` origin-checked. Android deep links need the internal token.
- No `service_role` in client bundles (prior session; not re-unpacked this session).

### SQLCipher / Keystore (this session, static + existing unit tests)

`DatabaseKeyManager` holds a 32-byte `SecureRandom` passphrase. Primary wrap: AES-GCM file under
`filesDir`, key in AndroidKeyStore. Legacy EncryptedSharedPreferences is migrated once then
cleared. Undecryptable file is **moved aside**, not deleted. F26 recovery: if **encryption** fails
(invalidated Keystore key), the alias is deleted and retried **once**; publish/rename failure must
not delete a healthy key. Tests: `DatabaseKeyManagerRecoveryTest`, `DatabaseKeyManagerTest`
(prior suite). **Not** re-run this session.

There is **no live passphrase rotation** while a populated DB exists (rekey would be a migration).
Uninstall + reinstall generates a new passphrase; the old ciphertext is unreadable — fail-closed.
**Corrupted-ciphertext recovery on device** is still **Blocked** (instrumented / real Keystore).

Desktop DB: unencrypted SQLite, accepted. Desktop session: `.supabase-session` wrapped with DPAPI
(`DesktopSupabaseSessionPersistence`). Decrypt/`UnsatisfiedLinkError` caught as `Throwable`;
undecryptable file is kept (F27). Fail-closed to signed-out. **Not** exercised in a packaged MSI
this session.

Android session: `AndroidSupabaseSessionPersistence` still uses deprecated
`EncryptedSharedPreferences` / `MasterKey` (compiler warnings on this session’s compile). Failover
path, not the SQLCipher passphrase path.
